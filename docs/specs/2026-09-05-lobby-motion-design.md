# Lumio 大厅动效高保真设计稿

## 目标

在现有 GameTech 视觉令牌、纸片卡片和体素几何基础上，把玩家大厅升级为更有游戏感的入口页。第一版只聚焦大厅首页，但所有动效都要能复用于登录、反馈、Roadmap 和后台页面。

## 视觉方向

采用“场景化大厅 + 在线状态轨道”。页面仍然是浅色、清晰、可扫描的游戏平台界面；游戏感来自空间层次、微型场景和状态变化，不来自大面积暗色背景或装饰性渐变。

继续使用以下既有令牌，不新增第二套色板：

- `--ui-primary` / `--ui-primary-d`：主交互和体素高光
- `--ui-mint`：在线、可进入、成功状态
- `--ui-amber`：活动提示和注意状态
- `--ui-rose`：即将上线和危险状态
- `--ui-title` / `--ui-muted` / `--ui-line`：文本与边界
- `.ui-card`、`.ui-btn`、`.ui-cover`、`.ui-grid-bg`、`.ui-voxel`：现有原语继续作为实现基础

### 顶部导航

沿用现有 `Header`。当前路由增加选中态底色和 120ms 颜色过渡；导航不新增常驻动画。移动端保留两行结构，账号操作始终保持可见。

### Hero 场景

- 高度：桌面 360px，移动端内容自适应，最小高度 300px。
- 左侧内容最大宽度 520px：kicker、44px 主标题、两行以内副文案、三个入口按钮。
- 右侧场景层由四个圆角体素块和一个 72px 主体素组成。体素块使用 `--ui-primary`、`--ui-mint`、`--ui-amber`、`--ui-rose`，透明度 0.45–0.78。
- 网格背景继续使用 `.ui-grid-bg`；额外增加一层低透明度的斜向轨道线，用于产生 3px 以内的鼠标视差，触摸设备不启用。
- Hero 进入时使用 `lm-in`；四个装饰块分别延迟 80ms、160ms、240ms、320ms，避免同时出现。

### 在线状态轨道

游戏目录标题右侧显示一条轻量状态轨道：绿色方点、全平台在线人数、最近更新标签。数据变化时只对数字做 180ms 的淡入淡出和 2px 上移，不推动布局。

### 游戏卡片

- 桌面最小宽度 320px，使用 `repeat(auto-fill, minmax(20rem, 1fr))`。
- 封面比例 16:10；每张封面保留白色 28px 网格线、左上分类胶囊和右下在线胶囊。
- 封面场景由 CSS 几何构成：主方块、两块阴影方块、一个小型旋转标记。场景只在卡片可见时播放 6–8 秒循环，暂停时不重排布局。
- 首发游戏卡片默认使用 `ui-card--pop`，其余卡片使用普通阴影。
- Hover：卡片 `translateY(-4px)`，封面场景向鼠标反方向移动最多 6px，主方块旋转最多 4deg；总时长 180ms。键盘焦点复用相同视觉状态。
- 点击“开始游戏”保留当前 `/launching/:slug` 路由和加载过场；点击分享只更新按钮文案和 toast。
- 未发布卡片降低到 0.78 opacity，场景动画降低为单次 1.2s 入场后暂停，确保“即将上线”不会与可进入状态混淆。

## 动效规格

### 动效 token

新增以下全局 token，放入 `web/src/styles/tokens.css`：

```css
--ui-motion-enter: 320ms;
--ui-motion-stagger: 80ms;
--ui-motion-float: 6.4s;
--ui-motion-hover: 180ms;
--ui-motion-slow: 900ms;
```

保留现有 `--ui-ease` 和 `prefers-reduced-motion` 规则。所有动画必须绑定这些 token，不写散落的长时长。

### 页面进入

1. 主容器 opacity 0 → 1，translateY 8px → 0，320ms。
2. Hero 内容延迟 80ms。
3. 游戏目录标题延迟 160ms。
4. 卡片按 DOM 顺序每张延迟 80ms，最多延迟 240ms。

### Hero 漂浮

使用 `lm-float`：translateY 在 -8px 到 8px、rotate 在 -4deg 到 4deg 之间循环，采用 ease-in-out。四个装饰块使用不同 duration（5.8s、6.4s、7.1s、7.6s）和不同 delay，形成错位节奏。主方块不自转，避免干扰品牌标记。

### 在线脉冲

在线胶囊的绿色方点每 2.6s 做一次 opacity 0.55 → 1 → 0.55，禁止扩散光晕。数字变化使用 `content` 不变的轻量过渡，防止读数跳动造成误解。

### 交互反馈

- 主按钮 hover 只提升亮度和阴影，active 下移 1px。
- 卡片 hover 不改变文字颜色和卡片尺寸。
- 分享成功 toast 使用现有 `modalIn` 风格，持续 1.8–2.2s。
- 所有装饰动画在 `prefers-reduced-motion: reduce` 下停止；结构、颜色和焦点态保留。

## 移动端规则

- Hero 改为单列，装饰层保留两个较小体素块，主方块放在标题右上角，不隐藏整个场景。
- 主标题降到现有响应式范围内，按钮允许换行但不缩小到低于 40px 高。
- 卡片变为单列；封面场景的视差完全关闭，仅保留低频漂浮。
- 在线状态轨道换到标题下方，避免右侧挤压。

## 可访问性与性能

- 动效只作用于 `transform`、`opacity`、`box-shadow`，不动画 width、height、padding 或布局属性。
- 装饰层全部 `aria-hidden="true"`，在线人数和状态胶囊使用真实文本。
- 交互元素维持现有 `:focus-visible` 焦点环，并让键盘焦点与 hover 状态一致。
- 不引入动画库或图片依赖；CSS 几何和现有头像资产足以完成第一版。

## 验收标准

1. `/` 首屏在桌面和移动端都保持清晰层级，游戏卡片无布局抖动。
2. Hero、卡片入场、悬停、在线状态和分享反馈均可观察到动效；启用减少动效后全部停止。
3. 现有登录、反馈、Roadmap、后台路由和 API 行为不改变。
4. 运行 `pnpm -C web verify` 通过，且至少覆盖大厅现有路由测试。
